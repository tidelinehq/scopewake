How it works

Four moments in the life of one approval. Scroll and they stack, like the file they become.

An owner approves the agent.

tideline approve records who approved what, for which agents, and freezes the reach they have today: servers, credentials, capabilities, cloud permissions.

Its access grows without notice.

A developer connects Stripe to the same agent. Nothing in the approval record changes, so the approval now describes an agent that no longer exists.

Scopewake flags the approval.

tideline review compares today’s reach with the frozen snapshot. Any addition marks the approval re-review required, with each reason and the MAS paragraph it maps to.

Questions buyers ask

Scopewake is built to open no network connection and write no files. It reports the names, kinds and locations of secrets, never their values. Tests and a source-policy check enforce this design; they are not a proof, so read the code and run it offline first.

Define a small pilot your team can evaluate in a week. Choose who leads it and where the first evidence comes from, and take the brief to your next meeting.

Team: Technology risk
Agent workflow: (name one agent workflow)

Plan
1. Record the approved baseline for this one agent with `tideline approve`.
2. Name the accountable reviewer and the approval owner.
3. Introduce one known access change in a test configuration.
4. Run `tideline review` and export the result (Markdown, CSV or JSON).
5. Decide together whether the evidence supports a useful review.

Out of scope: runtime enforcement, certification, legal opinion.
